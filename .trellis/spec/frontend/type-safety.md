# Type Safety

TypeScript is configured through astro/tsconfigs/strict in tsconfig.json. Keep
new route, layout, component, and utility code compatible with strict checking
and the existing path aliases.

## Type Organization

- Put shared site/config contracts in src/types.ts (Site and SocialObjects).
- Define component-specific props next to the component as an exported Props
  interface. This is the pattern in Header.astro, Layout.astro, Card.tsx, and
  Datetime.tsx.
- Use Astro's generated CollectionEntry<"blog"> type for content entries. Pass
  CollectionEntry<"blog">["data"] when a component needs only frontmatter, as
  Card.tsx and Search.tsx do.
- Keep the environment contract in src/env.d.ts; PUBLIC_SITE_LINE is explicitly
  narrowed to "domestic" | "overseas".

## Content Validation

src/content/config.ts is the runtime boundary for Markdown frontmatter. The
blog collection uses a Zod schema to validate dates, strings, tags, optional
flags, canonical URLs, and Open Graph images. The image branch enforces a
minimum 1200 x 630 size before a post can use a local image.

When adding a frontmatter field, update the schema first and then consume the
inferred field through CollectionEntry<"blog">. Do not cast arbitrary
frontmatter objects to make an invalid post compile.

## Typed Configuration Patterns

Use as const for closed configuration sets and derive unions from them. In
src/config.ts, SITE_LINES defines SiteLine, and WEBSITE_BY_LINE is a
Record<SiteLine, string>. The same file exports the typed SITE, LOCALE,
LOGO_IMAGE, and SOCIALS values.

Use literal unions for small prop variants (size?: "sm" | "lg") and
discriminated unions when the markup genuinely has two shapes, as in
Main.astro.

## Assertions and Escapes

Avoid any and broad type assertions. The only current assertion is the endpoint
boundary in src/pages/posts/[slug]/index.png.ts, where Astro's generic props
value is converted to CollectionEntry<"blog"> before passing it to the OG
renderer. Prefer improving a type contract over adding another assertion.

Route params are strings and can be absent or invalid. Reuse the defensive
numeric handling in getPagination.ts rather than assuming a dynamic segment is
valid.

## Common Mistakes

- Defining a second post/frontmatter type instead of using the content entry
  generated by Astro.
- Adding a social name that is not a key of src/assets/socialIcons.ts.
- Widening PUBLIC_SITE_LINE to arbitrary strings and losing the safe hostname
  lookup.
- Putting shared contracts in a page or component where other routes cannot
  reuse them.
